# 工具栏双行与中文输入修复

*日期 2026-08-10 分支 `dev_meta_spark_1.2`（含 55f1673 / 0dfd6ac / d883717 三批）*

> 前置：从 PixPin 抄来的「截图即得一根双行工具条」是表，输入法能打出中文是里；两件事在同一周被一起收口到**单一真相**（样式轴一个注册表、效果开关一个注册表、字符宽度一套 CTLine 算法）。

## 现象

1. **工具条挤**  
   截图确认后展开颜色/粗细等样式控件时，单行工具条被撑宽，越到小屏或钉图窄窗越挤； style 控件与工具/动作混在一行，分组语义看不出。

2. **文字打不了中文**  
   标注文字（`T` 工具）在截图覆盖层与钉图两处均不支持输入法合成：键入拼音时无 marked 态、无候选窗口，随手按回车才把拼音当正文落盘；光标/候选位置与真实字形宽度无关。

3. **样式与效果两套硬编码**  
   样式轴（颜色/粗细/字号/透明度/颗粒/压暗）的「档位/排序/标题/默认值/落盘键/图标绘制/应用到图层/烤进新图层」散在 `ToolStyle` / `AnnotationState` / `BuiltinControls` / `EditorToolbar` 四处各写一遍 `switch`；效果开关（水印/捕获信息/外壳/美化）的「标识/图标/工具条次序/面板标题/导出次序」在 `BuiltinControls` 与 `EditorEffectsPanel` 两处各自手写列表。新增一根轴或一个效果需要跨文件同步，易漏。

4. **工具条裸写 NSColor / 编辑器工具条手写顺序**  
   `ToolbarRenderer` 直接写 `NSColor(calibratedWhite:…)` 等字面量；图库编辑器工具栏 `EditorToolbar.toolOrder` 手写工具顺序，与 `BuiltinTools.all` 各管一摊，新增工具要改两处。

## 根因

* **布局**：`ToolbarLayout.blockSize` 为单行宽度，`slots(origin:)` 单行铺开，无「样式行」概念；钉图曾按可用宽度折行的路径本已拆除，但截图工具条仍无分行，`ToolbarRenderer` 只画一块底板。
* **输入**：`AnnotationState` 只有 `layers + editingTextID + pendingLayer`，无 `markedText` 中间态；`OverlayView` / `PinImageView` 未实现 `NSTextInputClient`，系统输入法找不到 `firstRect` 与 `setMarkedText/insertText` 的挂点。
* **样式真相分散**：`ToolStyleAxis.steps / order / title` 各自 `switch`，`ToolStyle.init(from:)` 手写六个 `decodeIfPresent`，新增轴必须同步改解码；`AnnotationState.applyStyle` 与 `makeLayer` 内对高亮/马赛克等特殊轴各写分支。
* **效果真相分散**：效果的开关、工具条上的 `EffectToggleControl`、面板里的分组卡片、导出编排的 `renderOrder` 未被同一个有序注册表驱动。

## 修复

### 1. 工具栏双行（PixPin 形态）— `ToolbarLayout` / `ToolbarRenderer`（55f1673）

`ToolbarLayout` 至多两行：**上行** `main = tools ∪ history ∪ actions`、**下行** `style = style 组`。仅当下行非空时启用双行；无样式自动退化单行（指针中性态等）。

* `blockSize(_:)` = `max(上行宽, 下行宽)` × 高（有样式 `34*2+8=76`，否则 `34`），「宽度取最大」保证两行等宽对齐，不因某行短而错位。
* `slots(origin:context:)`：有样式时主行在 `origin.y + rowHeight + interRowGap`、样式行在 `origin.y`；主行始终最靠近锚点（贴选区下方时主行在上，翻到上方时主行在下），`interRowGap = 8`。
* `rowSlots` / `rowWidth` / `rowFrames(of:)` 抽为独立计算，命中与绘制同用 `slots`，不存在「看到的位置与能点的位置不一致」。
* `ToolbarRenderer.draw` 改画**两块**圆角底板（各行一套 `NSBezierPath(roundedRect:)` + `DS.toolbarBackground/Stroke`），行间留 `interRowGap` 缝；选中/悬停高亮仍按 slot 套 `DS.toolbarSelected/Hover`。

### 2. 中文 IME 成闭环 — `AnnotationState` / `OverlayView+Keyboard` / `PinKeyboard` / `IMECaretGeometry`（0dfd6ac + d883717 精度收口）

* `AnnotationState.markedText: String?` —— 输入法合成串预览，不入撤销栈。`displayLayers` 在 `editingTextID` 行上若 `markedText` 非空则拼 `text + marked`，否则拼 `text + "|"`；`endTextEditing()` 清空 `markedText`，避免下次编辑带残影。
* 两宿主实现 `NSTextInputClient`：
  * `setMarkedText(_:selectedRange:replacementRange:)` → 写 `annotation.markedText` 并 `needsDisplay = true`；
  * `insertText(_:replacementRange:)` → 清 `markedText` 后走 `AnnotationState.insertText` 真正落盘；
  * `firstRect(forCharacterRange:actualRange:)` → 委托 `IMECaretGeometry`（见下），返回输入法候选窗口应跟随的矩形；
  * 并补 `selectedRange / markedRange / hasMarkedText / attributedSubstring` 等协议必需端。
* `IMECaretGeometry`（新增，纯函数无状态，占 `Sources/Index/Annotation/IMECaretGeometry.swift`）：
  * `prefixWidth(fullText:prefixLength:fontSize:)` 与 `lineHeight(for:fontSize:)` **均与 `Layer.handleBounds` 同源**：`NSFont.systemFont(ofSize:weight:.semibold)` + `CTLineCreateWithAttributedString` + `CTLineGetTypographicBounds`，避免 `NSString.size(withAttributes:)` 的字距/回退字体近似误差；`prefixLength` 按 UTF16 计（与 `NSRange.location` 一致），超界截断。
  * `overlayViewRect(layerRect:fullText:fontSize:prefixLength:boundsHeight:)`：覆盖层画布无缩放、左上原点，只做 Y 翻转 `boundsHeight - y - h`。
  * `pinViewRect(...,displayScale:)`：钉图画布为图片像素，视图等比缩放 + Y 翻转，`x/w` 乘 `scale`，字符宽高亦缩放。

### 3. 样式轴单一真相 — `ToolStyle.ToolStyleAxisDescriptor` 注册表（d883717）

`ToolStyleAxisDescriptor` 成为**唯一改动点**：

| 字段 | 含义 |
|---|---|
| `axis / order / title / steps / defaultIndex / codingKey / keyPath` | 轴的身份、排序、档位、默认值、落盘键与在 `ToolStyle` 上的存储位置 |
| `toolbarDraw: (CGRect,Int)->Void` | AppKit 工具条点阵（`BuiltinControls.ToolParamControl`） |
| `editorIcon: (Int,Bool)->AnyView` | SwiftUI 编辑器工具栏图标 |
| `applyToLayer: (inout Layer,ToolStyle,Double)->Bool` | 把当前样式应用到已选图层（`blockSize` 固定 `false`） |
| `bakeToLayer: (inout Layer,ToolStyle)->Void` | 新建图层时烤进可选字段（`blockScale/dim/opacity`） |

`ToolStyleAxisDescriptor.all` 静态注册六轴（`color 0 / width 100 / fontSize 200 / opacity 300 / blockSize 400 / dim 500`，三档语义与旧硬编码等价）。`ToolStyleAxis.steps / order / title` 退化为对 `descriptor` 的转发；`ToolStyle.index(for:)` / `setIndex(_:for:)` 改走 `keyPath`，不再 `switch`；`init(from:)` / `encode(to:)` 改为遍历 `all` 的动态键解码，新增轴无需再改编解码，老用户的旧偏好缺键时以 `defaultIndex` 兜底。

`BuiltinControls.ToolParamControl` 与 `EditorToolbar`（`styleAxes` 一行）改由 `descriptor.toolbarDraw / editorIcon / title / steps` 驱动，工具条与编辑器面板因此**同源**。

### 4. 效果开关单一真相 — `EffectRegistry` / `EffectDescriptor`（d883717）

`EffectDescriptor` 补 `id / symbolName / toolbarOrder / panelTitle` 四字段；`EffectRegistry` 四描述符（`watermark 320 / captureInfo 340 / windowShell 360 / backdrop 300`）以 `displayOrdered`（按 `toolbarOrder`）与 `ordered`（按 `renderOrder`）两套有序视图暴露：

* `BuiltinControls` 的 `EffectToggleControl` 与 `EditorEffectsPanel` 的分组卡片均按 `EffectRegistry.displayOrdered` 循环生成，硬编码列表收敛；
* 开关仍走 `AnnotationState.toggleEffect` / `hasEffect`，但判定与参数烤入由 `descriptor.makeLayer(EffectContext)` 统一承载，`EffectContext` 聚合 `imagePixelWidth/Height/pixelScale/chromeScale/watermark* /backdrop*` 注入，避免描述符直读 `AppSettings`；
* 导出编排 `LayerRenderer.render` 按 `renderOrder` 套用：水印 `0 → captureInfo 1 → windowShell 2 → backdrop 3`。

### 5. DS 令牌收口 — `DesignTokens` / `ToolbarRenderer` / `EditorToolbar` / `BuiltinTools`（0dfd6ac）

* `DS` 新增 `toolbarBackground / toolbarStroke / toolbarSeparator / toolbarSelected / toolbarHover` 五枚 AppKit 令牌，`ToolbarRenderer` 裸写 `NSColor` 全部改为 `DS.*`，满足 `check.sh` 纪律四；
* `EditorToolbar.toolOrder` 手写数组改为 `BuiltinTools.all.map(\.tool)`（`AnnotationToolDescriptor` 注册表为真相），新增工具只需在 `BuiltinTools.all` 加一行。

## 单测

* `ToolbarLayoutTests`（`0dfd6ac` 新增，5 项）：单行/双行判定、块宽取两行最大、命中与绘制同源（`rowFrames` 与 `blockSize` 高度一致）等纯函数用例，无 AppKit 依赖。
* `AnnotationIMETests`（`d883717` 新增/扩充，`80→95`），覆盖 `IMECaretGeometry.prefixWidth` 单调与超界截断、与 `CTLine` 独立测量的逐字符一致性、`lineHeight` 空串回退、overlay/pin 的翻转与缩放 `firstRect` 坐标、以及 `AnnotationState.displayLayers` 在 `markedText` 有/无时的光标/预览切换。
