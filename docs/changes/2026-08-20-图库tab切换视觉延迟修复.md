# 图库 tab 切换视觉延迟修复

*日期：2026-08-20*

## 背景

用户反馈：点击图库顶栏的 tab（图库 / 收藏 / 录屏 / 应用）时，「点了要等一下才切换」——tab 高亮和内容区切换都有可感知的延迟，四个 tab 都如此。

## 现象

- 视觉延迟：点击 tab 后渲染帧内有一段停顿，切换不是即时的；
- 四个 tab 全部受影响，说明卡点在 tab 切换的公共路径上，而不是某个具体页面；
- 搜索不卡：在顶栏输入搜索词时响应是即时的。

## 排查

先排除了两个常见嫌疑：

1. **数据库体积**：`index.sqlite` 仅 3.6MB / 261 行，`ocrText` 列总共 0.16MB。同步查询本身是毫秒级，单看耗时不足以解释「可感知的延迟」；
2. **缩略图解码**：`CachedImage` 走后台解码管线（`ThumbnailLoadPipeline`，ImageIO 强制解码 + 4 并发限制 + NSCache 缓存），不在主线程做像素解码。

再看 tab 切换的公共路径：

```text
点 tab → destinationID 变化
  → 旧视图 onDisappear → deactivate → reset() → reload()   ← 同步
  → 新视图 onAppear    → activate → reload()               ← 同步
```

一次 tab 点击触发**两次** `reload()`。而 `reload()` 底层是 GRDB 的 `.immediate` scheduling：

```swift
// ShotQueryRepository.observeLibrary
if immediately {
    return observation.start(in: database, scheduling: .immediate, ...)
}
return observation.start(in: database, scheduling: .mainActor, ...)
```

`.immediate` 的首次查询会**同步阻塞主线程**直到查询完成；加上每次 `publish` 的 `objectWillChange` + `libraryDidChange` 级联（多个视图 body 重算、后台 task 调度），渲染帧被拉长，tab 高亮和内容区切换都延迟。

对比搜索路径：`scheduleExactSearch` 走 `reloadInBackground()`（`.mainActor` 异步版），DB 查询在后台跑，主线程只响应点击——所以搜索不卡。

**结论：不是查询慢，而是查询跑在了渲染帧里。** 小库时是「等一下」，库大了会变成「卡一下」，但根因相同。

## 修复

`GalleryContentScope.activate` / `deactivate` 里的同步 `reload()` 改成异步 `reloadInBackground()`，把 DB 查询移出渲染帧：

```swift
// 改前
viewModel.reload()

// 改后（activate）
let query = viewModel.searchText
let filter = viewModel.filter
Task { await viewModel.store.reloadInBackground(query: query, filter: filter) }
```

要点：

- `activate`：先同步改好筛选状态（内存操作，微秒级），再异步重建查询；
- `deactivate`：清状态 + `filter = .all` + 异步 reload，切回图库 tab 时数据已就绪；
- 快速连点 tab 时 `deactivate` 和 `activate` 的异步 reload 会竞争，`restartLibraryObservation` 的 generation 计数器丢弃过期查询，只有最后一次生效；
- 数据就绪时序不变：异步查询完成后照常发布快照，网格照常刷新。

## 验证

- `./scripts/check.sh` 全绿：347 测试 0 失败 + 8 项架构纪律；
- `./build.sh release` 成功，用户实测确认「好了不卡了」。

## 教训

**渲染帧内不许有同步 DB 查询。** 图库 tab/destination 切换路径（`activate` / `deactivate`）上以后新增或修改数据加载逻辑时，检查是否引入了同步 DB 查询（GRDB `.immediate`、同步 `reload()`），一律用 `reloadInBackground()`。判断口径：凡是「用户点一下、UI 必须立刻响应」的路径，数据加载都必须异步。
